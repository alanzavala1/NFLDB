# Receiving-credit pilot

For the separate trial that executes the official R calculator, see
[Official nflfastR receiving split trial](UPSTREAM_SPLITS.md). Neither experiment
is imported by production code.

This isolated prototype tests whether individual provider stat credits can
correct receiving attribution before any production migration. Serving and
ingestion do not import it. It uses the existing pandas/DuckDB dependencies,
opens only an in-memory database, and accepts already-loaded frames; it has no
network, source-file write, provider-format reader or persistence path.

## Data flow

1. Read identified players' receiving credit records (stat IDs 21–24 and 115).
2. Aggregate **all** records by game, play and player, preserving repeated codes
   and negative yardage. Raw records are not deduplicated by player/stat code.
3. Join those player/play totals to one regular-season play context using both
   game ID and play ID. Reject duplicate context keys before they multiply rows.
   Exclude two-point conversions. Credits outside supplied play context are
   outside the query scope; unidentified players are excluded consistently with
   the existing weekly loader. Missing/nonfinite matched yard credits fail.
4. Group the result by down or quarter. Overtime uses the existing OT bucket.
   Rows without the requested context remain in play totals but not that split.

The result contains observed `target_credits`, receptions, receiving yards and
receiving TDs. **Observed target credits are not a claim of complete targets.**
The pilot does not calculate eligibility, catch rates, EPA, air yards, YAC,
first downs, target-depth splits, passing or rushing stats. A lateral recipient
can receive yards without a target/catch and can remain below split admission.

## Repeatable offline examples

From `api`:

```sh
uv run --locked pytest tests/test_receiving_credit_pilot.py
```

The small versioned JSON fixture records provider game/play/player IDs, minimal
play context, raw credit rows and manually reviewed expected receiving results.
Tests require no large snapshot, private cache, network, or RDS reader. The
expectations are not generated by the prototype under test.

The twelve real cases include normal and negative catches, Carter/Chapman,
Allen/Cooper, Saubert's repeated lateral credits, McConkey's negative lateral,
both Gibbs laterals, and the receiving side of the two-passer Dallas play.
Rushing/aborted-punt plays and a conversion are exclusion controls; these tests
do not establish correct passing/rushing calculations. Additional checks cover
cross-game play ID reuse, context duplication/missing keys, invalid yardage,
postseason/conversion filtering, unidentified players and missing-down/OT splits.

## Full cached-season evaluation (October 15, 2026)

The same prototype was also run against cached provider PBP, individual credits
and weekly summaries for 2001, 2004, 2006 and 2024. Minimal fixtures above are
checked in; large provider files and diagnostic scripts/reports remain ignored
in `api/data/`. The diagnostic report is `receiving-pilot-evaluation.json`.

| Regular season | Player/play rows | Identified receiving players | Receiving yards / catches / TD disagreements with weekly summaries |
|---|---:|---:|---:|
| 2001 | 15,831 | 428 | 0 at both player/game and player/season levels |
| 2004 | 9,781 | 442 | 0 at both levels |
| 2006 | 9,840 | 418 | 0 at both levels |
| 2024 | 17,043 | 502 | 0 at both levels |

Observed target credits also match those summaries, including the known gaps:
2004 has just 5 credits versus 9,773 receptions; 2006 has 67 versus 9,801.
Agreement between related provider products does not establish target coverage
or independently verified NFL accuracy. An observed count of zero must not
become a confident target total/rate. 2001 also has documented per-play target
disagreements with PBP; a target policy remains necessary even in seasons whose
league totals look plausible.

Grouping by down and quarter preserves all four measures for rows with the
respective context across the four samples. The 2024 Gibbs result is 517 yards,
52 receptions and 4 receiving TDs, including the two lateral credits without
adding catches/targets. This verifies this prototype's scope, not a passing
full-history candidate or every situational metric.

## Before production integration

Choose and validate the source adapter/storage lifecycle, define field/season
coverage and target semantics, preserve existing admission, and decide how
credits coexist with EPA and target-specific dimensions. Expand real-season
validation before replacing the receiving builder and retrying a full candidate.
The website, candidate preparation gate and serving-write migration are unchanged.
